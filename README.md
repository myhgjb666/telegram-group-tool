## 功能亮点

- **多账号管理**：添加多个 Telegram 账号，查看状态与今日已发 / 日上限
- **代理池（一号一代理 / 共用代理）**：批量导入 http / https / socks5 代理，可一键给每个账号自动分一个，也可以多个账号共用一个；账号列表直接显示每个号当前走哪条线路；「测试」做的是**真实握手**（让代理把隧道建到 Telegram），不是只看端口通不通
- **协议号批量登录**：直接把已经登录好的 `.session` 文件导进来，**不发验证码、不走二步验证**；支持一次多选文件或选中整个目录批量导入，逐个验证并显示成功 / 跳过 / 失败清单；同目录若有 `16803619008.json` 这类会话信息文件，会自动读取 `api_id` / `api_hash` 与设备信息，不用再手填
- **群组选择**：同步已加入群组，按任务勾选发送目标
- **消息模板**：支持多文案轮换与变量（日期、时间、群名等）
- **定时计划**：Cron 或固定间隔，可立即执行 / 暂停
- **防封控制**：发送间隔、日配额、白天窗口、抖动等可调
- **发送日志**：成功 / 失败原因可查，便于排查
- **关键词监听**：群消息或私聊命中关键字后自动私聊回复模板，带冷却与日上限
- **监听命中（手动确认）**：监听规则可切成「只记录不发送」——命中的用户进「监听命中」页，勾选要联系的人、选一套模板、确认后才真正发出，避免机器人式误回
- **公开群搜索**：按关键词搜索公开群 / 频道，可限速加入并设为发送目标
- **客户联系**：导入自己客户的手机号，识别其中哪些开通了 Telegram，逐个发送跟进消息（仅限自有客户，带永久退订与每日上限），识别后可一键把号码从 TG 通讯录清掉；导入时可按国别自动补区号（港澳台、东南亚、欧美等 30+ 常用国家/地区），号码支持多选批量删除与一键清空
- **限制中心**：显示 Telegram 限流倒计时，可查询官方 @SpamBot 的限制状态

## 快速上手

1. 下载并运行 `tg-broadcast-v0.2.36.exe`
2. 注册 / 登录软件账号（新设备通常有试用时长，到期后需续期）
3. 打开 [my.telegram.org/apps](https://my.telegram.org/apps) 登录，创建应用并拿到 `api_id` / `api_hash`
4. 在软件 **账号** 页添加 Telegram 账号（填写 api 凭证 + 手机号，完成验证码 / 二级密码）
   - 如果手上是**已经登录好的 `.session` 协议号**，点「导入 .session…」即可跳过验证码，见下一节
5. 在 **群组** 页发现并勾选目标群
6. 在 **消息模板**、**定时计划** 中创建内容与计划，开始发送

## 用 session 协议号批量登录

手上已经有一批登录好的协议号（`.session` 文件）时，不需要一个个走短信验证码，直接在 **账号** 页点 **「导入 .session…」**。

### 步骤

1. **选文件**：点「选择文件…」可一次多选，点「选择目录…」可整个文件夹导入（勾「包含子目录」会连同子文件夹一起扫）。
   选完立即在本地解析，列表里逐行显示结果，例如 `Telethon · DC 2`；坏文件在联网之前就标红。
2. **api 凭证：能自动读就不用填**。v0.2.34 起会先找**同目录的会话信息文件**（例如 `16803619008.json`、`session.json`，卖家发货时通常和 `.session` 放一起），里面有 `app_id` / `app_hash`（或 `api_id` / `api_hash`）就直接回填，列表里会标「自带 api（xxx.json）」。找不到这类文件时才需要手填一套；勾「记住」后，以后导入只需选文件。会话文件本身不存 `api_hash`，所以两者都没有时这一步绕不开。
3. **点「导入并验证」**：程序连上 Telegram 取到账号信息后才写库。列表按 **绿色成功 / 黄色跳过（该账号已在列表）/ 红色失败** 显示，鼠标悬停看完整原因。

### 支持的格式

| 格式 | 是否支持 | 说明 |
|---|---|---|
| Telethon `.session` | ✅ | 最常见 |
| Pyrogram `.session` | ✅ | 无服务器地址，按 DC 表补齐 |
| 纯文本 StringSession | ✅ | `.session.txt` / `.txt`，有些渠道给的是文本 |
| Telegram Desktop 的 `tdata` 文件夹 | ❌ | 结构完全不同，不是同一种会话文件 |

**不会改动你的原文件**：程序只读取里面的 auth_key，用的是临时副本，读完即删，原文件字节与修改时间都不变。

### 批量导入的节奏

- 顺序执行，**每个文件之间停 1～2 秒**（含随机抖动），不会让几十个账号在同一秒接连上线。
- 单个文件失败只记一行，**继续下一个**，不会因为一个坏号中断整批。
- 只有 api 凭证本身填错时才会整体中止，避免把同一个错误重复几十遍。
- 中途可点「停止」；跑完后窗口不会自动关闭，方便查看哪些失败了。

### 三个必须知道的限制

1. **`.session` 等于这个账号的完整控制权**。别人给的号，对方手里留着同一份密钥，随时能登回去把你挤下线。导入后建议到手机端 **设置 → 设备** 把不认识的会话全部下线。
2. **一条会话的「设备」显示不会因为导入而改变**。那里显示的是当初授权时的设备（可能是手机或某个库），本地改设备信息只影响之后新建的授权。
3. **两步验证密码不会保存在文件里**。会话活着时用不到；一旦失效要重新登录，需要你自己记得那个密码。

导入后的账号和手动登录的账号**完全一样**：断线重连、群发、定时计划、关键词监听、客户联系、日配额全部通用，没有区别对待。

## 代理池：一号一代理 / 共用代理

以前所有账号只能共用一个全局代理入口，多号同 IP 上线容易被一起盯上。v0.2.33 起新增 **代理池** 页面：批量导入代理后，可让每个账号各走一条线路，也可以指定几个号共用一条。

### 步骤

1. **导入代理**：顶部「代理池」页 → 粘贴代理列表，或「从文件导入」。支持两种写法，可以混着写：
   - 完整 URL：`socks5://user:pass@1.2.3.4:1080`、`http://user:pass@1.2.3.4:8080`
   - 冒号格式：`1.2.3.4:1080:user:pass`（端口必填，账号密码可省）
2. **测试一批**：点「测试全部」，每条代理会做一次**真实握手**——SOCKS5 打招呼（需要时带用户名密码）→ 让代理把隧道建到 Telegram 的服务器，成功才显示「可用」。只验端口是不够的：很多线路 443 端口活着（前面挂了 CDN），但代理服务早就没了，握手会被直接断开。
3. **分配**：点「自动分配」，程序按顺序给**还没绑定代理**的账号各分一条（已绑定的不动）；也可以在账号编辑里逐个指定。绑定会立刻保存，随后单独重连，重连失败不会影响绑定结果。
4. **查看**：账号列表新增「代理」列，实时显示每个号走的是哪一条；代理池列表会显示每条代理被几个账号用着（大于 1 就是共用了）。

### 支持的协议

| 协议 | 写法 | 说明 |
|---|---|---|
| HTTP | `http://...` | 常见低成本代理 |
| HTTPS | `https://...` | 按 HTTP 隧道方式处理 |
| SOCKS5 | `socks5://...` | Telegram 场景推荐，支持带用户名密码 |

### 怎么看「可用 / 不可用」

代理列表的「连通状态」列只有三种值：

| 状态 | 含义 |
|---|---|
| 未测试 | 刚导入，还没有测过（升级后旧的测试结论会自动作废，回到这个状态） |
| 可用 | 握手成功，代理确实能把流量送到 Telegram |
| 不可用 | 鼠标停上去看具体原因：端口假活 / 需要 IP 白名单 / 用户名密码被拒 / 代理拒绝转发到 Telegram / HTTP 407 等 |

实测常见的一句是「**端口能连上，但代理握手时被对端直接断开**」——这条代理已经失效了，换线路，别在它身上调参数。

- **测完再分配**：几十条代理先「测试全部」（6 路并发，单条最多约 20 秒），把「不可用」的删掉或换掉，再点「自动分配」。
- **换了一批代理后**：绑定关系还在旧代理上，新代理测好之后重新「自动分配」或手动绑定；只想让现有绑定重连一次，点「重连已绑定账号」。
- 设置页的「测试代理连通」（全局代理）用的是同一套判定，结论一致。

### 几个要注意的地方

- **导入后马上生效**：改动某个账号的代理后，该账号会自动断开重连一次，不需要手动重启软件。
- **绑定失效不会退化成直连**：如果某条代理被删了、坏了或者填错，账号会**自动回落到全局代理**，而不是直接裸连暴露你的真实 IP。
- **凭据加密存储**：代理的用户名密码加密后存本地，列表里不显示明文；同一条代理（地址 + 凭据）重复导入会自动去重。
- **改全局代理仍然有效**：没绑定专属代理的账号，继续走「设置」里的全局代理。

## 常见问题

**Q: 打不开 / 闪退？**  
A: 确认是 64 位 Windows；可尝试以管理员运行，或把 exe 放到无英文路径目录。

**Q: 收不到 Telegram 验证码？**  
A: 验证码一般发到 Telegram App（不一定是短信）；检查手机号是否国际格式（如 `+86...`）。

**Q: 发送很慢或经常被跳过？**  
A: 先看 **发送日志** 的「状态」列（筛选切到「全部」，别只看已发送），再看「耗时」列：  
① 大量「重复内容跳过」＝同一份静态文案在「重复内容时间窗」内只能发一个群，到 **参数设置** 把它调小即可提速；  
② 文案里带 `{{group_name}}`、`{{random}}` 这类变量时，每个群内容都不同，不会被判重复（`{{random}}` 每次生成 3 位字母+数字，写成 `{{random8}}` 可加长）。  
③ 日志出现「flood_wait Ns」或账号页显示限流倒计时＝被 Telegram 限流，等待倒计时结束即可，同时建议放慢节奏、增加文案变化，避免账号被进一步限制。  
④ 「耗时」列（v0.2.25 起只统计这一条发送本身，不含发送间隔）出现几十秒甚至 120 秒以上＝网络 / 代理慢，换更稳定的线路比调参数更有效；软件现在会自动换掉变慢的连接，状态栏会显示「已重建 N 次」。  
⑤ 其他跳过原因（群冷却、日上限、非活跃时段）都在日志与账号页可见。默认值偏保守，可按需微调，但不建议拉满。  

**Q: 客户号码没有 +86 前缀，能直接导入吗？**  
A: 能。「客户联系」导入时选好「国别」（默认中国大陆），不带 `+` 区号的号码会按所选国别自动补全；号码自带 `+` 区号的以号码为准，不受国别选择影响。清单里删错了也没关系：可按住 Ctrl / Shift 多选后批量移除，或用「清空全部」重头再来（会弹两次确认，已发送的日志不受影响）。

**Q: 有些群明明能手动发，软件却一直不发？**  
A: 检查群列表该行是否标记为「拉黑」（第 5 列显示「是」，或右上角统计里的「N 个拉黑」）。旧版本会把 Telegram 的临时限制误判成永久封禁并拉黑，这类群被拦住了。右键该群选「解除拉黑（恢复可选）」；数量多时直接右键账号行，选「解除全部拉黑（N 个群）」一次清理，然后重新勾选即可。v0.2.27 起临时限制不会再被拉黑。

---

**Q: 我有已经登录好的 `.session` 协议号，还要收验证码吗？还要自己填 api 吗？**  
A: 都不需要（多数情况）。账号页点「导入 .session…」，选文件（可多选，也可选整个目录）→ 若同目录有 `xxx.json` 这类会话信息文件，`api_id` / `api_hash` 会自动回填，列表标「自带 api」→ 点「导入并验证」，全程不发验证码、不走二步验证。只有目录里没有这类 json 时才需要手填一套凭证。导入不会修改原文件。详见上文 [用 session 协议号批量登录](#用-session-协议号批量登录)。

**Q: 监听能不能不自动回复，先自己看一眼再决定发不发？**  
A: 可以。编辑监听规则时把「响应方式」改成 **手动**：命中只记录用户和消息内容，不会自动发出。之后到「监听命中」页按规则 / 状态筛选，勾选要联系的人 → 选一套消息模板 → 点发送并确认，才会真正发出去。同一用户再次命中会合并成一条（带命中次数），发送前会显示人数与预计时长，也能中途停止。

**Q: 导入时提示「auth_key 已注销 / 会话已作废」？**  
A: 说明这个会话已经失效：可能是账号被登出、改过密码，或者同一份文件在别处同时使用（Telegram 会把先前的会话作废）。这类文件只能重新走一次短信登录，救不回来；同一个账号也不需要重复导入，程序会直接提示「已在列表」。

---

**Q: 我想让每个账号走不同的代理，能做到吗？**  
A: 可以。到「代理池」页导入代理（支持 `socks5://user:pass@ip:port`、`http://...` 和 `ip:port:user:pass` 三种写法，也能从文件整批导入），再点「自动分配」，程序会给还没绑定的账号按顺序各分一条。想让几个号共用一条也行，列表会显示每条代理被几个账号用着。绑定后该账号自动重连，账号列表的「代理」列能看到当前线路。

**Q: 某条代理挂了 / 被我删了，账号会不会直连暴露真实 IP？**  
A: 不会。绑定的代理失效或被删除时，账号会自动回落到「设置」里的全局代理；只有全局代理也没配时才会直连，跟以前的行为一致。

**Q: 代理显示「可用」，但还是连不上 / 分配后大量失败？**

**Q: 登录时提示「无法安全连接授权服务 / 证书校验失败」？**  
A: 意思是登录请求的加密连接被中途替换了，跟你的账号无关。按提示里的签发者判断：① 提示「证书由 XXX 签发但不匹配地址 / 不是常见公共证书颁发机构」→ 当前 VPN / 代理 / 公司网络对该连接做了拦截，**换一个节点**，或在代理规则里让授权服务地址直连（`DIRECT`）后重试；② 提示「证书已过期」→ 升级到最新版本；③ 提示「证书正常但本机校验失败」→ 多为**系统时间不对**（右键任务栏时间 → 校准）或本机根证书过期。换 VPN 后出现这个提示，基本都属于第 ① 种。
